# UUID 身份更新部署（客户端 20261017）

客户端只使用稳定电脑 UUID 识别用户，不再生成、保存或发送令牌。已登记的同一 UUID 直接沿用服务器原用户记录；重新下载软件、丢失或损坏旧凭据不会重新发放试用，也不会阻止已有 UUID 用户查询授权。

## 服务端先更新

1. 停止宝塔中的原 Python 项目，备份当前实际使用的 SQLite 数据库（通常为 `/www/wwwroot/douyinDown/payment.db`）。
2. 只上传并覆盖以下两个文件，目录结构与服务器保持一致：
   - `服务端/payment_server/app.py` → `/www/wwwroot/douyinDown/payment_server/app.py`
   - `服务端/payment_server/service.py` → `/www/wwwroot/douyinDown/payment_server/service.py`
3. 启动原 Python 项目，启动命令、依赖及反向代理规则不变。
4. 再运行新客户端测试。该版本必须配套更新后的服务端，旧服务端仍要求令牌。

本次不修改数据库结构，不上传或覆盖数据库、`.env`、`payment_server/config.py`、`models.py`、`database.py` 和 `videoDown.txt`。用户 ID、首次登记时间、禁用状态、订单、授权期限和下载总数保留。旧的 `token_hash` 字段保留用于兼容旧客户端；UUID 新用户写入非认证用途的唯一占位值。

上线前可在本机运行 `python -m pytest tests -q`，覆盖临时数据库、模拟支付及本机演示服务；不使用线上数据库或真实微信交易。

## 客户端与旧用户

- 解压完整客户端目录，运行 `DouyinDownloader.exe`；不能只复制 exe，需保留旁边的 `_internal`。
- 已有电脑 UUID 用户直接沿用原身份，不再依赖 `payment_credentials/`。
- 早期随机编号用户首次升级时，保留 Windows 用户目录或原软件目录中的 `payment_credentials/`。新版只读其中的旧设备编号，将服务器原记录和全部订单关联至电脑 UUID，原到期时间不变；旧文件不覆盖、不删除。
- 新位置已经存在无效的新凭据时，仍会查找软件目录中找回的旧随机编号。损坏、不可读及非当前服务的旧文件会跳过。
- 关联响应丢失后可以重试；已经关联成功的 UUID 即使旧文件全部丢失也可继续使用。
- 两个不同编号在服务器上都已有用户记录时不自动合并，需人工核对。早期随机编号未关联且旧编号已全部丢失时，不能只凭硬件 UUID 推断出原记录，仍需人工恢复。

旧客户端的原令牌认证保留。带 UUID 请求头的已发布客户端，即使令牌变更，也能凭同一 UUID 继续访问；更早仅发送 Bearer 的客户端继续使用原有效令牌。

## 测试包与更新提示

客户端版本为 `20261017`，数字日期版本只在远程版本更高时提示更新，避免线上旧版本配置引导测试用户降级。本次无需修改公开更新文件或网盘链接，确认测试包可用后再单独发布正式更新信息。
