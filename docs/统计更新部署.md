# 用户统计更新部署

此次先上传服务端，再使用新版客户端。现有客户端仍可使用支付接口，但不会上报本次新增的启动和下载统计。

## 宝塔服务端

1. 在宝塔停止当前 Python 项目，备份正在使用的 SQLite 数据库（通常是 `/www/wwwroot/douyinDown/payment.db`）。保留原 `.env` 和 `payment_server/config.py`。
2. 上传本项目 `服务端/payment_server/` 中的 `app.py`、`database.py`、`models.py`、`service.py` 和 `stats_page.py`，覆盖服务器 `/www/wwwroot/douyinDown/payment_server/` 中对应的五个文件。保留服务器的 `.env`、数据库和 `config.py`，不会覆盖服务器上 0.01 元测试套餐的设置。源码仓库不包含本地测试压缩包；新增更新信息接口的部署步骤另见 [更新信息部署](更新信息部署.md)。
3. 启动原 Python 项目，启动命令和依赖不变。首次启动会在数据库旁生成 `payment.schema-backup-时间-编号.db`，将 `payment_devices` 改为 `users`、`payment_orders` 改为 `orders`，并移除 `payment_download_reports`。用户 ID、UUID、订单、授权、最近打开时间和已有下载总数均保留；尚无统计字段的旧记录补齐字段，下载总数初始化为 0，未知最近打开时间留空。再次启动不会重复迁移。
4. 确认域名反向代理转发 `/stats` 和 `/api/pc/*` 至当前 Python 项目。若现有代理转发整个站点，无需增加单独规则。
5. 打开 `https://douyindown.secs.cc/stats`，应显示四个数字；`https://douyindown.secs.cc/api/pc/stats` 应返回相同汇总结果。无需登录，也不展示电脑编号、订单或用户明细。

升级后累计用户数包含现有测试设备，不清空数据。活跃数据从新版客户端首次成功启动上报开始统计，旧的授权查询时间不会填入最近打开时间。

如需回退，先停止项目，再恢复升级前的代码与数据库备份。升级后新增的订单与统计不会存在于旧备份中，回退前应另行保存当前数据库。

## 客户端

Windows 电脑标识与令牌保存于 `%LOCALAPPDATA%\QingningVideoDownloader\`。更新软件或删除软件目录不会删除这些记录。旧版软件目录的 `payment_credentials/` 在首次新版启动时会导入，因此第一次升级请将新程序覆盖到原软件目录，或将原 `payment_credentials/` 复制到新版程序目录，待成功启动关联后再整理旧文件。

当前使用 `python main.py` 进行客户端源码测试，不生成客户端程序包或压缩包；以后仅在明确要求发布时打包。客户端已配置正式域名，应先更新宝塔服务端再启动。

新电脑优先使用 SMBIOS UUID，读取失败时备用使用 MachineGuid。原始硬件值只用于本机生成 UUID；请求仅携带生成的电脑 UUID 和设备令牌。缓存来源后不会因临时读取失败切换编号。MachineGuid 备用方案不承诺重装 Windows 后保持一致。

旧随机编号凭有效令牌关联到电脑 UUID，保留原数据库 ID、首次登记时间、订单和授权期限。已有电脑身份冲突时不自动合并；全部本机凭据丢失时联系客服恢复，服务器仍保留原记录，不能重新领取同一电脑的试用。

每个成功保存的视频计一次，音频、图文及失败不计。计数先写入本机队列，再后台上报；网络失败保留队列，下次联网重试。服务器收到有效增量就直接累计，不再使用下载去重表；网络回复丢失后的重试可能多计，按简单统计口径接受。

标题仅显示“青柠视频下载”，左侧导航包含下载、登录、设置和说明。说明页显示客户端版本号、作者微信和教程入口，体验期间不显示收费或授权信息。后台仍进行启动登记、下载统计和使用前校验。试用或付费期限到期后，点击下载或重试才弹出授权窗口；启动软件不会弹购买窗口。窗口内直接显示套餐选择，点击“立即支付”后原地显示金额和微信二维码。付款成功且授权验证有效后自动关闭并继续原下载操作，关闭窗口则不下载。窗口提供刷新状态及作者微信提示，不显示复制设备编号按钮；网络异常和设备禁用不视为到期。

## 统计口径

- 今日活跃：北京时间今天 00:00 至当前启动过的电脑数量。
- 近 7 天活跃：今天及前 6 个自然日。
- 近 30 天活跃：今天及前 29 个自然日。
- 累计用户数：设备表总记录数。

同一电脑在一个范围内只计一次。授权查询、付款轮询和下载上报均不修改最近打开时间。只保留最近打开时间，因此此版本不支持查询过去某天的历史日活。

## 接口

`POST /api/pc/startup` 携带 Bearer 设备令牌，提交 `{ "uuid": "电脑 UUIDv5" }`，完成旧身份关联及启动上报，返回 `id`、`uuid`、`first_opened_at`、`last_opened_at`、`downloaded_video_count`、`expires_at`。时间由服务器记录并以 UTC ISO 8601 输出。

`POST /api/pc/download-count` 携带同一设备令牌，提交 `uuid` 和正整数增量 `count`（一次最多 1000000）。每次收到有效请求都直接累加；旧版附带的 `report_id` 被忽略，不参与去重。返回当前 `downloaded_video_count`。

`GET /api/pc/stats` 公开返回 `today_active`、`active_7d`、`active_30d`、`total_users`，以及计算时刻 `as_of` 和 `timezone`。页面与接口都禁止缓存。
