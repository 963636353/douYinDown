# 客户端问题反馈

左侧「问题反馈」支持手动提交问题或建议。页面打开时仅获取上传限制；只有用户点击「提交」才会收集诊断日志并发送反馈，不进行自动错误上报。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `core/feedback/models.py` | 不可变表单、附件、回执、上传限制和可展示的错误 |
| `core/feedback/client.py` | HTTPS 地址校验、multipart 请求、状态码及限流解析；无自动重试 |
| `core/feedback/diagnostics.py` | 限量读取近期日志，过滤凭据、链接和用户目录，生成 UTF-8 TXT |
| `core/feedback/service.py` | 复用电脑身份、重新检查截图、组合必带日志、协调配置和提交 |
| `gui/feedback_worker.py` | 后台执行任务，通过 Qt 信号回到主线程；退出后不更新界面 |
| `gui/feedback_tab.py` | 表单、文件选择、提交状态、失败保留内容和等待倒计时 |
| `gui/feedback_dialogs.py` | 简单的反馈成功提示 |

接口地址默认为 `https://bug.secs.cc`，独立于支付和更新服务。维护者可通过环境变量 `QINGNING_FEEDBACK_API_BASE` 覆盖，正式地址必须使用 HTTPS；HTTP 仅允许 `localhost`、`127.0.0.1` 或 `::1` 本机调试。接口无 API Key，不发送抖音 Cookie、支付凭据或授权令牌。

## 提交与附件

- 页面首次显示时后台读取 `GET /api/config`。提交前再次读取，失败时沿用最近有效配置或文档默认值；服务端最终校验仍生效。
- `POST /api/feedback` 始终使用 multipart。文字字段各一次，多个文件重复使用 `attachments`，不使用 `attachments[]`。
- 日志固定附带，占一个文件名额。默认最多添加 4 张 JPG/JPEG/PNG 截图；截图和日志一并计算附件总量及整个请求大小。
- 为日志预留最多 64 KiB 的空间。默认单文件 10 MiB、附件合计 15 MiB、整个 multipart 请求最多 16 MiB；用户截图不会被自动压缩或修改。
- 提交时重新读取有界文件快照，检查消失、变更、空文件和超限文件，避免只依赖选择截图时的检查。
- 电脑标识沿用 `ComputerIdentity` 和原有 `computer.json`。不重新生成反馈专用随机身份，不要求支付服务连接成功。

## 诊断信息

日志附件为 `recent_diagnostics.txt`，包含软件版本、同一电脑 UUID、系统和 Python 版本、生成时间，以及 `logs/app.log` 最近的运行记录。

最多读取日志尾部 256 KiB，保留最近 400 行，最终诊断文件最多 64 KiB。日志不存在或不可读取时仍提交包含环境信息和说明的非空 TXT。不会读取 Cookie、凭据文件、下载内容或其他历史日志。

导出前隐藏 URL 的路径与查询参数、用户目录名、可识别的 Cookie、Authorization、token、签名等凭据字段；包含凭据键值的整行会被隐藏。该过滤用于既有状态日志，不代表任意未来新增的日志内容都能自动识别，新增日志时仍应避免记录秘密。截图和用户主动填写的正文按原内容提交。

## 结果处理

- 仅 HTTP 202、`ok=true` 和有效反馈编号视为成功；表示已接收，不表示邮件已送达。
- 成功后清空已提交的描述和截图，保留微信，仅弹出「反馈已收到，感谢你的反馈！」，不展示编号，并等待设备最短提交间隔后允许再次提交。
- 提交失败弹窗统一显示「发送失败，失败原因：……。可以联系作者微信z851968反馈」，保留服务端原因或网络异常中的结果未确认说明。
- 失败保留本页草稿和截图；草稿只保存在内存中，关闭软件不会持久保存。
- 429 遵循 `Retry-After` 与 JSON `retry_after` 的较长等待时间，倒计时结束不会自动提交。
- 网络超时、异常的成功响应和可能已处理的网关错误提示「提交结果未确认」，不自动重发，避免重复邮件。
- 兼容代理返回的 HTML 错误页。服务端错误文字以纯文本显示。
- 退出时忽略晚到的结果；已发出的请求可能已被服务器处理，关闭软件不会撤销反馈。

## 验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_feedback*.py" -v
```

协议测试使用模拟响应和本机 HTTP 服务，不会向正式反馈服务提交或触发邮件。GUI 测试使用真实 Qt 控件和假服务，覆盖重复点击、界面响应、失败保留内容、倒计时、关闭时的晚到响应及成功、失败提示。
